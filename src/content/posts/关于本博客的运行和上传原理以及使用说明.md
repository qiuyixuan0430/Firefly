# 一、基本原理

##   1、网站运行

　　本博客的基本模板来自于CuteLeaf大佬制作的一个github开源项目，我对其进行了一些修改和加工。本博客网站的内容和源码全部保存在本人的github仓库，包括博客中的文章、自动检查部署流程、网站配置、后端文章编辑器等。我在这里讲述一下本项目的运行原理。

![](/uploads/pasted-image-1785080965733.png)

　　网站生成器使用了Astro,可以将仓库中的材料输出为HTML、CSS、Javascript、图片、索引等。其中图片会被压缩，转换，生成响应式版本。

   　　自动化整体借助了github Actions，其中包含两套自动任务，一套负责检查格式问题，一套则用来做网络部署。

   　　网站托管借助github Pages，它将保存并公开由Actions生成的dist，它只提供静态文件，无需长期运行的Node.js后端，无需服务器管理。

  　　域名托管则借助了伟大的 CloudeFlare DNS，DNS 会把该网站的子域名指向博客的托管服务。域名只是网站入口，不保存博客文件。

   　　评论系统使用Giscus，评论管理位置在 GitHub 仓库的Discussions中，而不是文章文件中。

   　　本地开发环境在powershell中执行pnpm dev，使用其启动Astro的本地预览，本地预览用于测试代码和配置，不会自动修改线上网站。只有提交并同步到 GitHub，且自动部署成功后，线上网站才会更新。

##   2、网站维护

   　　本网站的维护和更新流程一般借助vscode进行代码修改，保存后进行本地提交，随后和github仓库进行同步，github Action检查无误后，推送至网页前端。

![vscode 截图](/uploads/f65889a8c6ba3745ab8071b684bbbdc0.png "vscode 截图")

  　　特别的，vscode大部分时间都需要代理才能够连接上github仓库，同步失败时在vs终端执行：

    http.proxy http://127.0.0.1:（） （）中是自己的代理端口。

    git pull --rebase origin master

   　　即可。

## 3、文章发布

   　　本博客文章发布采用了纯vibe coing的方法，编写出了一套无需使用markdown，也可以在线编辑博客的在线编辑器，该编辑器使用Sveltia CMS，它使用github token操控github仓库，实现类似word一样的图文编辑器功能，并且可以将文章推送到github仓库中，不依赖外部CDN。

![在线编辑器](/uploads/1d119fe392adc9e1a145b4b4d24e1c44.png "在线编辑器")

   　　目前此编辑器还在持续升级中，后续将会添加更多功能，使得其能够真正对标word?希望吧（笑。

# 二、用户互动

#   1、PC端

   　　我其实重点的对PC端进行了很多前端上的适配，使用PC端浏览的体验会更佳，界面如下图所示：

![](/uploads/%E5%9B%BE%E7%89%871%281%29.png)

![](/uploads/%E5%9B%BE%E7%89%872%281%29.png)

①：社交，内含友链和留言功能，留言功能暂时仅支持github登录的用户留言。

②：我的，包含动态，相册和追番功能，相册有普通相册和加密相册，追番功能目前链接了本人的Bilibili追番表，后续可能还会添加bangumi番剧计划。

③：搜索：可搜索博客内的文章，包括标题和内容。

④：音乐：见⑫。

⑤：视频背景：目前暂无视频，后续会加。

⑥：主题：可自主调节网站的颜色，展示形式。

⑦：背景：可选择浅色、深色、或跟随系统，默认为深色。

⑧：博客内的横幅图片为5秒轮播，以及图片上展示的文字均可编辑。

⑨：分类：这里很重要，后续会上线包括游戏、动漫、语言、电路设计、教程、课程、数学等分类

⑩：头像：点击进入简介。

⑪：链接：这里只有github链接有效，其它的我都返回了blank。

⑫：音乐：这里链接了我的一个网易云歌单，给我留言，可以添加音乐至歌单。

## 2、移动端

   移动端界面和PC端不同。

![](/uploads/%E5%9B%BE%E7%89%873.png)

⑬：菜单：集成了PC端导航栏的部分功能。

⑭：排版：移动端默认文章为列表排版。

⑮：移动端的个人信息需要下滑可以看到。

#### 特别注意，在平板电脑上，横屏会被识别为PC端，竖屏则会切换为移动端界面，过程中可能会卡顿，且平板PC端的页面适配效果较差，并不推荐使用平板浏览该网页。
